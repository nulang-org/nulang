## Try Nulang without installing

The [browser playground](/playground/) runs the **Nulang Core subset** locally in WebAssembly. It does not support actors, networking, FFI, JIT, or the full native runtime. For those capabilities, install a binary.

## Install a tagged release (recommended)

Tagged releases publish checksummed archives on [GitHub Releases](https://github.com/nulang-org/nulang/releases). **A release asset is available only after its release workflow has completed successfully.** You do not need Rust or the Nulang source tree to install a published binary.

| Platform | Release archive |
| --- | --- |
| Linux x86_64 | `nulang-linux-x86_64.tar.gz` |
| Linux aarch64 | `nulang-linux-aarch64.tar.gz` |
| macOS Apple Silicon | `nulang-macos-aarch64.tar.gz` |
| Windows x86_64 | `nulang-windows-x86_64.tar.gz` |

Download the archive **and matching `.sha256` file** from the same tagged release. Choose the archive for your operating system and CPU architecture.

### Linux example (x86_64)

From the directory containing the downloaded files:

```bash
sha256sum -c nulang-linux-x86_64.tar.gz.sha256
tar xzf nulang-linux-x86_64.tar.gz
mkdir -p "$HOME/.local/bin"
install -m 0755 nulang-linux-x86_64 "$HOME/.local/bin/nulang"
"$HOME/.local/bin/nulang" --eval 'perform IO.print("Hello, Nulang!")'
```

Add `$HOME/.local/bin` to `PATH` if it is not already there. For Linux aarch64, replace `linux-x86_64` with `linux-aarch64` in the commands.

### Linux distro packages (new releases)

Releases published **after the distro packaging workflow is merged** also
include native packages for each Linux architecture. Earlier tagged releases
retain their existing generic archives.

| Distro family | x86_64 / amd64 | ARM64 / aarch64 |
| --- | --- | --- |
| Ubuntu, Debian, Linux Mint, Pop!_OS | `nulang_<version>_amd64.deb` | `nulang_<version>_arm64.deb` |
| Fedora, RHEL-compatible, openSUSE | `nulang-<version>-1.x86_64.rpm` | `nulang-<version>-1.aarch64.rpm` |
| Arch, Manjaro, EndeavourOS and other glibc-based Linux | `nulang-linux-x86_64.tar.gz` | `nulang-linux-aarch64.tar.gz` |

Select an existing release tag from [GitHub Releases](https://github.com/nulang-org/nulang/releases),
then substitute it for `vX.Y.Z` below. Install from a package only after
verifying its adjacent checksum.

**Ubuntu / Debian (x86_64):**

```bash
TAG=vX.Y.Z
BASE="https://github.com/nulang-org/nulang/releases/download/$TAG"
curl -fLO "$BASE/nulang_${TAG#v}_amd64.deb"
curl -fLO "$BASE/nulang_${TAG#v}_amd64.deb.sha256"
sha256sum -c "nulang_${TAG#v}_amd64.deb.sha256"
sudo apt install "./nulang_${TAG#v}_amd64.deb"
nulang --version
```

**Fedora (x86_64):**

```bash
TAG=vX.Y.Z
BASE="https://github.com/nulang-org/nulang/releases/download/$TAG"
curl -fLO "$BASE/nulang-${TAG#v}-1.x86_64.rpm"
curl -fLO "$BASE/nulang-${TAG#v}-1.x86_64.rpm.sha256"
sha256sum -c "nulang-${TAG#v}-1.x86_64.rpm.sha256"
sudo dnf install "./nulang-${TAG#v}-1.x86_64.rpm"
nulang --version
```

Substitute `arm64` for Debian filenames or `aarch64` for RPM filenames
on ARM64. To uninstall, use `sudo apt remove nulang` or
`sudo dnf remove nulang`. For Arch/Manjaro use the checksummed tarball
instructions above; no official `pacman`/AUR package is published.

**Linux compatibility boundary:** Release binaries are compiled on
Ubuntu 22.04 to target glibc 2.35 and OpenSSL 3. Debian 12, Ubuntu 22.04
and newer compatible environments are candidates for verification, **not**
an across-the-board support guarantee. RHEL/Rocky/AlmaLinux 9 ship glibc
2.34 and are not compatible with this build baseline. Alpine uses musl,
so these glibc binaries do not support native Alpine installation.
Check `ldd /usr/bin/nulang` for missing libraries and use a local source
build when the ABI is unsuitable. Do not work around an ABI mismatch with
fake symlinks.

### macOS (Apple Silicon)

After downloading both release files:

```bash
shasum -a 256 -c nulang-macos-aarch64.tar.gz.sha256
tar xzf nulang-macos-aarch64.tar.gz
mkdir -p "$HOME/.local/bin"
install -m 0755 nulang-macos-aarch64 "$HOME/.local/bin/nulang"
"$HOME/.local/bin/nulang" --eval 'perform IO.print("Hello, Nulang!")'
```

Add `$HOME/.local/bin` to `PATH` if needed. A macOS Intel binary is not currently part of the release matrix; building from source is an alternative on supported systems.

### Windows (x86_64)

Download the two `nulang-windows-x86_64` release files. On PowerShell, compare the SHA-256 digest returned by `Get-FileHash .\nulang-windows-x86_64.tar.gz -Algorithm SHA256` with the value in the downloaded `.sha256` file **before** extracting.

```powershell
tar -xzf .\nulang-windows-x86_64.tar.gz
Rename-Item .\nulang-windows-x86_64 nulang.exe
.\nulang.exe --eval 'perform IO.print("Hello, Nulang!")'
```

The release archive contains a platform-qualified executable that must be renamed `nulang.exe`. Move it to a dedicated folder on your `PATH` if you want to invoke `nulang` from other directories.

**Prebuilt CLI feature profile:** The current release workflow uses the
`release-cli` feature set (standard compiler/runtime tooling excluding Python
interop). It rejects dynamic `libpython` requirements in Linux binaries. Existing
published release assets may predate that protection; verify each downloaded
binary and its runtime dependencies rather than assuming a prior release was
rebuilt. macOS and Windows shared-library requirements vary by host.

**Support boundary:** CI builds and package-integrity checks are not a promise
of portability to every distribution. Nulang remains alpha software.

## Build from source (contributors and custom profiles)

A source build requires:

- **Rust 1.95.0**, pinned by `rust-toolchain.toml` ([rustup](https://rustup.rs))
- **Python 3** development headers for the default PyO3 interop feature
- A native C compiler and linker (plus other native dependencies of enabled features)
- Linux or macOS. On Windows, the documented source-build route is **WSL**; the Windows prebuilt executable above is separate.

```bash
git clone https://github.com/nulang-org/nulang.git
cd nulang
cargo build --locked --release
./target/release/nulang --eval 'perform IO.print("Hello, Nulang!")'
```

Source builds with all default features can be costly. For a smaller compiler/runtime build, use `--no-default-features`; this changes which optional integrations are available.

### Feature Flags

Nulang supports optional features for leaner builds:

```bash
# Minimal build (no Python, SQLite, LSP, AI runtime, or networking)
cargo build --release --no-default-features

# With WASM backend
cargo build --release --features wasm-backend

# All features
cargo build --release --all-features
```

| Feature | Default | Description |
|---------|---------|-------------|
| `native-codegen` | On | Cranelift-backed tiered JIT and the native/AOT backend |
| `python` | On | PyO3 Python interop |
| `sqlite` | On | libsql/Turso persistence |
| `lsp` | On | tower-lsp language server |
| `ai-runtime` | On | AI runtime — LLM providers, pipelines, debates, supervisor teams |
| `tls` | On | TLS support for the TCP transport |
| `ffi` | On | Dynamic native library loading (`extern` FFI) via libloading/libffi |
| `tcp` | On | Raw TCP networking — distributed-actor transport, HTTP server, metrics/registry/DAP servers |
| `ureq` | On | Synchronous HTTP client for `Http.get`/`Http.post`, the registry client, and `nula deploy` |
| `wasm-backend` | Off | WASM compiler + Wasmtime runtime (enables `--backend wasm\|wasm-run\|wasm-aot`) |
| `wasmfx-backend` | Off | WasmFX stack-switching backend for suspending effects (requires `wasm-backend`) |
| `http-client` | Off | Async HTTP client (reqwest) |
| `rocksdb` | Off | RocksDB persistence backend |
| `postgres` | Off | PostgreSQL persistence backend |
| `otel` | Off | OpenTelemetry observability |
| `difffuzz` | Off | Differential fuzzing driver binary |

## Verify a source build

```bash
# Run the test suite
cargo test

# Start the REPL
cargo run -- --repl

# Run a Nulang program
cargo run -- examples/01_hello.nula
```

## System-Specific Notes

### Fedora Linux

Install Python development headers:

```bash
sudo dnf install python3-devel
```

The `build.rs` script automatically creates a `libpythonX.Y.so` symlink for PyO3 linking.

### macOS

Install Python via Homebrew:

```bash
brew install python@3.14
```
