Nulang is an open-source, **alpha** programming language and runtime.
Contributions can be documentation improvements, clearer error messages,
small bug reproductions, runnable examples, conformance tests, editor tooling,
or focused implementation fixes.

## Find a contribution

- **[Roadmap](https://github.com/nulang-org/nulang/blob/main/ROADMAP.md)**:
  current priorities and their live issue trackers.
- **[Open issues](https://github.com/nulang-org/nulang/issues)**:
  bugs, proposed changes, and implementation tasks.
- **[Contributor guide](https://github.com/nulang-org/nulang/blob/main/CONTRIBUTING.md)**:
  build, tests, PR workflow, and compatibility requirements.
- **[GitHub Discussions](https://github.com/nulang-org/nulang/discussions)**:
  questions, onboarding, and early design feedback.
- **[New issue](https://github.com/nulang-org/nulang/issues/new/choose)**:
  use the bug, documentation, or feature template when a report is ready.

If you are new to the codebase, start with a small documentation or test
improvement and link to a concrete problem. Browse [curated starter issues](https://github.com/nulang-org/nulang/issues?q=is%3Aissue+is%3Aopen+label%3Agood-first-issue)
to find a scoped first contribution. The queue can be empty; comment before
starting to avoid duplicated work.

## What maintainers look for

A focused problem statement, reproducible evidence, minimal scope, tests or
a deterministic documentation check, and an explanation of unverified claims.
[GitHub Actions](https://github.com/nulang-org/nulang/actions) validates the
latest PR commit. The
[review playbook](https://github.com/nulang-org/nulang/blob/main/.github/CONTRIBUTOR_REVIEW_GUIDE.md)
explains how issues become claimable and what reviewers check.

Changes to Frozen or Stable semantics follow the
[governance and RFC process](https://github.com/nulang-org/nulang/blob/main/GOVERNANCE.md).
Please do not report vulnerabilities publicly; use the
[security policy](https://github.com/nulang-org/nulang/blob/main/SECURITY.md).
