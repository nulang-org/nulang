# Bootstrap self-hosting: evidence and next gates

Status assessment: 2026-10-15, based on `main` and repository history. This is **not** a release certification.

## Verified in repository history, not re-run for this report

- Commit [`0c19d60`](https://github.com/nulang-org/nulang/commit/0c19d60a01ad5679ebfc3bb64947fcb98141738b) (2026-09-11) records a successful local `bash bootstrap/verify.sh`, including check 7's six self-compilation oracle cases.
- `bootstrap/verify.sh` on `main` **does enable** check 7; the earlier investigation in `bootstrap/CHECK7_STATUS.md` is historical. The previous `bootstrap/README.md` claim that check 7 is disabled was stale.
- Stage 1: `compile_hex.nula` compiles a restricted Core subset to intermediate hex text. Python `fixup_hex.py` and `hex2nbc.py` turn it into `.nbc`.
- Stage 2: the Nulang-written emitter can compile its own preprocessed source under the six recorded oracle inputs. This is **not** full Nulang compiler self-hosting; Rust's VM still executes the compiler and Python assists the pipeline.

## Current validation gates

Run from the repository root after building `/tmp/cargo-target/debug/nulang` (the target directory
set by `.cargo/config.toml`):

```sh
python3 -m unittest discover -s scripts/tests -p test_bootstrap_differential.py
NULANG_BIN=/tmp/cargo-target/debug/nulang bash bootstrap/verify.sh
python3 bootstrap/verify_differential.py --nulang /tmp/cargo-target/debug/nulang
```

The additional differential runner, executed in `bootstrap-contract.yml`, builds a temporary Stage 2 compiler, compares its uncommented emission with Stage 1 for a curated JSON corpus, turns **both** emissions into `.nbc` files, and checks the VM's final result against a fixed expected value. It uses a temporary directory and fails closed on non-zero commands, empty output, timeouts, malformed fixtures, generation differences, and incorrect results. No generated bytecode is written into the checkout.

**Evidence boundary:** agreement between two generations of `compile_hex.nula` is *not* differential testing against Rust's full frontend. The fixed expected outcomes prevent both generations from silently agreeing on a wrong result for these cases, but they do not prove type-checker parity, error compatibility, or complete Core coverage. GitHub CI must execute the exact PR head before this new gate can be called passing. A zero-job GitHub Actions run is not execution evidence.

## Follow-up milestones (ordered)

1. **Broaden independently checked Core cases.** Add valid and invalid samples one-by-one, including nested closures, shadowing, operator boundaries, parser errors and diagnostic contracts. Only bless a case after reference behavior has been inspected; do not add unsupported syntax as a passing expectation.
2. **Eliminate Python from the bootstrap path incrementally.** First implement a Nulang-native equivalent of `fixup_hex.py` and verify byte-for-byte output on a fixed corpus; next replace `hex2nbc.py`. Only then evaluate removing source preprocessing (`prep_core.py`, `desugar_fns.py`). Retain the Python path as a differential oracle until proven equivalent.
3. **Expand compiler capabilities by semantic slice.** Add module parsing, typing, effects and canonical IR only when conformance and reference-compiler comparisons support them. Avoid wholesale Rust source translation.
4. **Prove reproducible multi-generation bootstrap.** Capture stage-N and stage-(N+1) artifacts on a pinned host, compare canonical artifacts and behavior, and record toolchain/version/bytecode identity. Do not infer a reproducible fixpoint from six matching hex outputs.
5. **Evaluate a minimal independent Core VM** only after prior gates pass; running `.nbc` in the Rust VM does not confer toolchain independence.

Priority: keep compiler/VM semantic correctness, exact-head CI, and durable execution safety ahead of full self-hosting. This workstream should remain narrowly scoped while those P0 invariants are open.
